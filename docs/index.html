Features

✅
No account needed
Uses the anonymous Android flow — rotates device IDs automatically.
✅
OpenAI-compatible
Same request/response shape as api.openai.com/v1. Works with existing SDKs.
✅
Streaming
Real-time SSE chunks, same format as OpenAI's streaming API.
✅
JSON mode
response_format: {type: "json_object"} forces a valid JSON response.
✅
Web search
Automatic, or controlled with web_search: true/false.
✅
File attachments
Upload PDF, code, or text files and reference them in messages.
✅
Multi-turn conversations
History is preserved per-session (30 min TTL).
✅
Multi-user
Each Bearer token gets its own isolated session pool and file store.
✅
Quota auto-recovery
On 429/403 the session is recycled and the request is retried transparently.
✅
Advanced tools & Canvas
Reservations, shopping, interactive widgets, collaborative documents.
❌
Image input
Vision not available in anonymous mode.
❌
Function calling
The anonymous backend never returns tool_calls.

Requirements

  • Python 3.11 or newer
  • fastapi, uvicorn[standard], httpx, pydantic, python-multipart
  • pdfplumber — optional, required only for PDF parsing
  • Network access to android.chat.openai.com

Installation

Local (pip + uvicorn)

bash
# Clone the repo
$ git clone https://github.com/your-user/chatgpt-proxy.git
$ cd chatgpt-proxy

# Create and activate a virtual environment
$ python3 -m venv .venv
$ source .venv/bin/activate   # Windows: .venv\Scripts\activate

# Install dependencies
$ pip install -r requirements.txt

# Optional: PDF support
$ pip install pdfplumber

# Run on port 8000
$ uvicorn main:app --host 0.0.0.0 --port 8000

Docker

bash
$ docker build -t chatgpt-proxy .
$ docker run -d -p 8000:8000 --name chatgpt-proxy chatgpt-proxy

Docker Compose

bash
$ docker compose up -d

The service will be available at http://localhost:8888 (mapped from container port 8000).

Quick start

Once the server is running, send a request using any OpenAI-compatible client:

curl
$ curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "messages": [{"role": "user", "content": "Hello! What can you do?"}]
  }'
response
{
  "id": "chatcmpl-a4f2e1d0c3b2...",
  "object": "chat.completion",
  "model": "auto",
  "choices": [{
    "message": {
      "role": "assistant",
      "content": "Hi! I'm ChatGPT. I can help you with..."
    },
    "finish_reason": "stop"
  }],
  "usage": { "prompt_tokens": -1, "completion_tokens": 42, "total_tokens": 42 }
}

Endpoints

POST /v1/chat/completions Main chat endpoint

Drop-in replacement for POST api.openai.com/v1/chat/completions. Accepts both streaming and non-streaming requests. Supports system prompts, file attachments, web search, JSON mode, and all other extensions documented below.

GET /v1/models Available models

Returns the model list available in anonymous mode, plus legacy OpenAI aliases (gpt-4o, gpt-4, gpt-3.5-turbo). Results are cached for 5 minutes.

curl
$ curl http://localhost:8000/v1/models
response — available model slugs
"auto"         ← default, picks best model
"gpt-5-6"      ← GPT-5.6 (Luna)
"gpt-5-5"      ← GPT-5.5
"gpt-5-6-mini"
"gpt-5-5-mini"
"gpt-5-3-mini"
POST /v1/files Upload a file

Upload a text or PDF file. Returns a file_id that can be referenced in subsequent chat messages. Files are stored in memory, isolated per API key, and are cleared when the server restarts.

curl
$ curl http://localhost:8000/v1/files \
  -F "file=@report.pdf;type=application/pdf" \
  -F "purpose=assistants" \
  -H "Authorization: Bearer my-key"

Also available: GET /v1/files (list), GET /v1/files/{id} (info), DELETE /v1/files/{id}.

GET /v1/session/me Anonymous session info

Returns the anonymous user object from /backend-anon/me — useful for debugging. Shows the current device_id and the anonymous ua-xxx user identifier assigned by ChatGPT.

curl
$ curl http://localhost:8000/v1/session/me
GET /health Server status

Returns version, active session count, file count, and the full capabilities object.

curl
$ curl http://localhost:8000/health

Request fields

All fields accepted by POST /v1/chat/completions:

Field Type Default Description
modelreq string "auto" Model slug. Use auto, gpt-5-5, gpt-5-6, etc. Legacy aliases (gpt-4o, gpt-4) are accepted.
messagesreq array Array of {role, content} objects. Roles: system, user, assistant.
stream boolean false Stream the response as SSE chunks.
response_format object null {"type": "json_object"} to force a valid JSON response. See JSON mode.
web_search boolean null Override web search. true = always search, false = never, null = model decides.
force_use_tools boolean null Enable advanced backend tools (reservations, shopping, genui widgets).
force_use_canvas boolean null Enable Canvas / document mode. Response includes :::writing{...} blocks.
tools array null OpenAI tools array — accepted for compatibility. Function names are mapped to backend flags (web_search → search, anything else → tools).
tool_choice string null "none" disables all modes. "auto" / "required" enables them.
temperature, max_tokens, top_p… various Accepted for compatibility but ignored — the anonymous backend does not expose these controls.

Streaming SSE

Set "stream": true to receive response chunks as Server-Sent Events. The format is identical to OpenAI's streaming API.

curl
$ curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  --no-buffer \
  -d '{
    "model": "auto",
    "stream": true,
    "messages": [{"role": "user", "content": "Count to 5 slowly"}]
  }'

In addition to the standard content chunks, the proxy emits two extra SSE events that are silently ignored by clients that don't recognise them:

EventWhenData
search_metadata After web search was used {queries: [...], sources: [...], title: "..."}
widgets When genui widgets are present [{name: "...", data: {...}}]

JSON mode

Pass "response_format": {"type": "json_object"} to force the model to respond with a valid JSON object. The proxy injects a system instruction and also passes the parameter to the backend. Markdown code fences are automatically stripped from the response.

curl
$ curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "response_format": {"type": "json_object"},
    "messages": [{
      "role": "user",
      "content": "Return a JSON object with the fields: name (string), age (number), city (string). Use fictional data."
    }]
  }'
response — choices[0].message.content
{
  "name": "Elena Marquez",
  "age": 29,
  "city": "Barcelona"
}

Web search

The model uses web search automatically when it determines a query needs current information. You can override this behaviour:

curl — force search on
$ curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "web_search": true,
    "messages": [{"role": "user", "content": "What happened in tech news today?"}]
  }'

When search is used, the non-streaming response includes a search_metadata object:

extra field in non-streaming response
"search_metadata": {
  "queries": ["tech news today August 2026"],
  "sources": [
    { "url": "https://techcrunch.com/...", "title": "TechCrunch", "attribution": "TechCrunch" }
  ],
  "title": "Tech news — August 16, 2026"
}

You can also control search via the standard OpenAI tools array:

OpenAI tools format → web search
{
  "model": "auto",
  "tools": [{ "type": "function", "function": { "name": "web_search" } }],
  "messages": [{ "role": "user", "content": "Latest news" }]
}

Advanced tools

Setting "force_use_tools": true enables ChatGPT's full tool suite: real-time reservations, shopping results, interactive widgets (genui), and more. Results are returned as text with an optional widgets field.

curl
$ curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "force_use_tools": true,
    "messages": [{"role": "user", "content": "Find me a hotel in Paris for this weekend"}]
  }'

Canvas mode

Canvas enables collaborative document editing. The response text includes special :::writing{...} blocks that contain the document structure.

curl
$ curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "force_use_canvas": true,
    "messages": [{"role": "user", "content": "Write a product requirements document for a task manager app"}]
  }'

File attachments

Upload a file first, then reference its file_id in a message using the multipart content format.

step 1 — upload
$ curl http://localhost:8000/v1/files \
  -H "Authorization: Bearer my-key" \
  -F "file=@contract.pdf;type=application/pdf"
# → {"id": "file-a3b4c5d6e7f8...", "status": "processed", ...}
step 2 — use in message
$ curl http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer my-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "file", "file": {"file_id": "file-a3b4c5d6e7f8..."}},
        {"type": "text", "text": "Summarise the key obligations in this contract."}
      ]
    }]
  }'

Multi-turn conversations

The proxy detects continuations by hashing the message history. Send the full conversation on each request — the proxy reuses the underlying session automatically.

turn 1
$ curl http://localhost:8000/v1/chat/completions \
  -d '{"model":"auto","messages":[{"role":"user","content":"My name is Ana."}]}' \
  -H "Content-Type: application/json"
# → "Hello Ana! How can I help you?"
turn 2 — include full history
$ curl http://localhost:8000/v1/chat/completions \
  -d '{
    "model": "auto",
    "messages": [
      {"role": "user",      "content": "My name is Ana."},
      {"role": "assistant", "content": "Hello Ana! How can I help you?"},
      {"role": "user",      "content": "What is my name?"}
    ]
  }' -H "Content-Type: application/json"
# → "Your name is Ana."

Multi-user / API keys

Each Authorization: Bearer <token> value gets a completely isolated namespace: its own session pool, its own file store, and its own quota tracking. Users without a header all share the anonymous namespace.

curl
$ curl http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer user-alice" \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello"}]}'

Quota handling

The anonymous flow assigns a message quota to each device_id (a UUID generated per session). When the quota is exhausted the backend returns HTTP 429 or 403.

♻️
Automatic recovery: when a session hits its limit the proxy marks it as exhausted, creates a fresh session with a new device_id, and retries the current request transparently. The client receives the normal response without any interruption. If the second attempt also fails (IP-level limit), the proxy returns HTTP 429 with an OpenAI-formatted error.
error response when fully exhausted
{
  "error": {
    "message": "Anonymous message limit exhausted. A new device_id will be used on the next request.",
    "type":    "rate_limit_exceeded",
    "code":    "rate_limit_exceeded"
  }
}

OpenAI SDK compatibility

Point any OpenAI-compatible client at the proxy by changing the base URL:

Python — openai SDK
from openai import OpenAI

client = OpenAI(
    base_url="http://localhost:8000/v1",
    api_key="any-string",  # required by the SDK but not validated
)

response = client.chat.completions.create(
    model="auto",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(response.choices[0].message.content)
Python — streaming
with client.chat.completions.stream(
    model="auto",
    messages=[{"role": "user", "content": "Write a haiku about rain"}],
) as stream:
    for chunk in stream:
        if chunk.choices[0].delta.content:
            print(chunk.choices[0].delta.content, end="", flush=True)
Python — JSON mode
import json

response = client.chat.completions.create(
    model="auto",
    response_format={"type": "json_object"},
    messages=[{
        "role": "user",
        "content": "Return a JSON object with keys: status and timestamp."
    }],
)
data = json.loads(response.choices[0].message.content)
print(data)

Known limits

  • No image input. The anonymous flow does not support vision. Uploading images returns HTTP 415.
  • No function calling. The backend never returns tool_calls — responses are always plain text.
  • No image generation. DALL·E requires an authenticated account.
  • File storage is in-memory. Uploaded files are lost on server restart.
  • IP-level quota. If many sessions share the same IP, the transparent device_id rotation may still hit an IP-level limit. The proxy surfaces this as HTTP 429.
  • Streaming JSON mode. Streamed chunks in JSON mode may include the JSON object split across multiple chunks; concatenate them before parsing.
  • Session TTL is 30 minutes. Idle sessions are evicted. Sending a message to an evicted session creates a new one automatically.
